The intended appliance stack

Local security visibility, built around the Raspberry Pi.

OMEGA targets a Raspberry Pi 5 with 8 GB RAM, running Raspberry Pi OS Lite 64-bit on Debian 13. The project brings network and endpoint observations, device context, retained evidence, reporting and local AI explanations into one operator dashboard.

What is a Raspberry Pi?

A Raspberry Pi is a small, general-purpose computer built on a single circuit board. The Pi 5 includes an Arm processor, memory, Ethernet, Wi-Fi and USB ports. It can run Linux software and serve as a compact dedicated computer. In OMEGA, the Pi provides the intended hardware platform for the dashboard, collector and supported local security services.

8 GB RAM is the working memory used by running programs. The operating system, collected records and reports need separate persistent storage, such as a microSD card. Raspberry Pi OS Lite is Linux without a full graphical desktop; Debian 13 identifies its underlying Linux distribution release, and 64-bit identifies the targeted software architecture. OMEGA supplies a browser dashboard for the operator.

The intended appliance needs suitable power, cooling and storage, plus configured data sources and private browser access. About Raspberry Pi 5 · About Raspberry Pi OS.

Suricata IDS + EveBox

Suricata is the network Intrusion Detection System (IDS): it inspects visible traffic, raises alerts for configured detection rules, and supplies EVE JSON activity. EveBox provides an additional interface for reviewing Suricata events. Useful coverage depends on the configured sensors and network visibility.

Wazuh SIEM/XDR + Pi agent

Wazuh provides Security Information and Event Management (SIEM) and Extended Detection and Response (XDR). A Wazuh agent on the Pi collects configured host events and connects to a separately provisioned Wazuh manager. OMEGA reads configured manager alerts and JSON archives through restricted SSH/rsync access; the agent alone is not a complete SIEM and does not provide manager logs. The full Wazuh central platform is provisioned separately.

Pi-hole

DNS observations and separately configured DNS blocking, with network or DHCP observations that help build device context. OMEGA's optional family preferences do not themselves activate filtering.

Tailscale + Fail2ban

Tailscale supports separately provisioned remote access. Fail2ban can provide externally configured host protection against repeated authentication failures; it is not packaged, pinned or configured by this preview.

Ollama + Qwen3

The intended on-appliance AI runtime explains selected evidence and suggests checks for operator review. It does not execute commands or block traffic. AI inference is disabled in the fictional demo.

OMEGA dashboard + operator tools

Python and SQLite power persistent collection, device labels, new-device notifications, correlation, evidence exports and paired setup. Nine Bash-based commands cover status, triage, reports, diagnostics and retention review.

SIEM analyzes security events; IDS inspects network traffic. OMEGA brings their available observations together with DNS activity, device context and evidence reports. Suricata can also operate as an Intrusion Prevention System (IPS) when configured for inline enforcement; this preview does not claim inline blocking. About Wazuh SIEM · About Suricata IDS/IPS.

The intended image uses Docker/containerd for Pi-hole and EveBox, systemd for service management, and an experimental rpi-image-gen builder with pinned package, container and model inputs. These external dependencies require their own provisioning and configuration. See the complete software stack and version boundaries.

Defense and investigation examples

Understand suspicious activity. Preserve the evidence.

DFIR means Digital Forensics and Incident Response. These examples describe a properly configured deployment, not attacks stopped by the fictional demo. Blocking depends on separately configured controls; OMEGA's dashboard and AI do not execute containment actions.

Repeated SSH password guessing

An externally configured Fail2ban jail can temporarily ban an address after repeated failed logins. Wazuh can report collected authentication events through its separate manager.

Investigation value: Review recorded attempts, targeted accounts, timestamps and any subsequent successful login, where those events were collected and retained. Fail2ban documentation.

A device requests a blocked malicious domain

Pi-hole can refuse DNS resolution when a domain matches configured blocking rules and the device uses that resolver. OMEGA can show collected DNS observations and device context.

Investigation value: Identify which observed device requested the domain and when. A blocked lookup alone does not establish infection. Pi-hole examples.

Scanning or suspicious network traffic

Suricata can alert when traffic visible to its sensor matches configured detection rules. EveBox offers another event-review interface. An operator can investigate and use separately managed containment controls.

Investigation value: Examine available addresses, ports, signatures, protocol details and timing. OMEGA does not automatically block these connections. Suricata event output.

Unexpected changes to important files

Configured Wazuh file-integrity monitoring can alert on changes to monitored files. The Pi agent covers its configured sources; other endpoints need their own agents or collection.

Investigation value: Investigate the reported file change and available hashes, attributes and timestamps. The manager must supply the relevant events to OMEGA. Wazuh file-integrity monitoring.

Exposed administration services

Properly configured Tailscale access controls can restrict administration to authorized users and devices, reducing the need to expose services publicly.

Investigation value: Reduce an access path while investigating through an authorized private connection. This does not establish that OMEGA collects Tailscale audit logs. Tailscale access controls.

Malicious text or unsafe paths aimed at OMEGA

Synthetic adversarial tests exercise command injection, forged result markers, unsafe paths and hostile text handling to catch failures in how the software treats untrusted input.

Investigation value: More reliable handling helps distinguish collected content from trusted application output. These are software checks, not evidence that a live attack was stopped. OMEGA test source.

A fictional investigation sequence

  1. 10:01: A monitored laptop requests a suspicious domain.
  2. 10:02: Suricata records a network alert involving its observed address.
  3. 10:03: Wazuh reports a change to a monitored startup file.

When those events are collected, an investigator can compare records, verify timestamps and device mappings, and decide what to preserve or investigate next. Shared timing or an address is a lead, not proof of compromise. A Suricata event relayed through Wazuh is not independent corroboration.

Evidence for investigation and handoff

Completed full-report exports on a configured live collector include a readable assessment, coverage/correlation JSON, retained normalized events and original collected sensor records from a consistent snapshot. Retention limits and unavailable sources remain visible. Local AI explains aggregates and selected examples; investigators must verify its conclusions.

Formal forensic work still needs acquisition tools, preserved originals, verified timestamps and a documented chain of custody. OMEGA does not provide disk/memory acquisition, complete packet capture or immutable evidence storage. Keep real incident evidence out of public issues. Read the full defense and DFIR guide.

Adversarial and failure-mode testing

Public test cases cover hostile input, command injection and forged result markers; authentication, origins, CSRF and session expiry; unsafe paths and permissions; interrupted operations, rollback, concurrency and evidence preservation. Image/payload tampering tests have a separate acceptance scope.

  • 272 distinct Python tests and 42 browser-logic checks.
  • 365 strict installer assertions, with the isolation audit passed.
  • 3,669 command-layer security-results assertions, with the isolation gate passed.

These are recorded results, not a new run for this page. The totals use different units and are not counts of distinct attacks. Synthetic adversarial and regression checks are not an independent penetration test or proof of appliance security. Explore the tests and read the dated validation report.

This demonstration does not monitor a live network or run AI inference. OMEGA is experimental source software; appliance-image and hardware acceptance remain separate. Read the validation results.
